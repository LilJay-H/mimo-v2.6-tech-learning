# 01｜MiMo V2.6 到底公开了什么

调研快照：**2026-09-22**。本文将“官方宣称开放”“实际找到文件/代码”“已经运行复现”分开。本次完成前两类中的资料核验，**没有执行模型训练，也没有复现官方分数**。出处索引见 [来源与核验边界](06-sources-and-limits.md)。

## 先回答：这些东西适不适合零 ML 基础的计算机学生？

**适合用来认识真实大模型训练，但不适合作为第一套逐行编程教材。** 可以现在阅读发布说明、认识训练流程，稍后动手检查任务、奖励和 Agent 轨迹；真正的第一次参数训练，建议交给更小、更透明的 Karpathy 教学模型。

这里的“小模型”是相对于数千亿、万亿参数模型而言，并不等于能在普通笔记本上轻松做完整强化学习。更关键的是：发布的 9B 已经接受过预训练和监督微调。拿它继续 RL，经历的是**后训练闭环**，不是从随机参数起步的完整预训练过程。[M3]

## 一、逐项资源地图

### 1. 官方发布文章：说明“为什么做、做出了什么”

小米在 2026 年 9 月 22 日的官方文章中介绍了 MiMo-V2.6-Pro、Flash，以及围绕强化学习公开的模型、环境、框架与技术报告。对初学者，这篇文章最有价值的不是排行榜，而是把训练拆为三件事：让模型更多地尝试任务，提供更多可交互的任务环境，以及投入更多资源判断结果是否真的好。它是全景介绍，不是安装后照着运行的课程。[M1][M2]

入口：[中文发布说明](https://mimo.mi.com/docs/zh-CN/news/latest/v2-6) · [英文发布文章](https://mimo.xiaomi.com/mimo-v2-6/article)

### 2. MiMo-V2.6-Pro-RL：大型模型的成品权重

[Pro 模型仓库](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-RL)提供模型权重、配置、模型卡、分词及部署相关文件。模型卡的架构口径为 **1.02T 总参数、42B 激活参数**，MIT 许可证，支持文本、图像、视频和音频输入。可以把权重理解成“模型训练后记住的数字”，而不是“教你训练它的完整过程”。它对你目前主要是架构阅读和 API 体验对象，不是本地训练对象。[M4]

### 3. MiMo-V2.6-Flash-RL：较小的旗舰模型，仍不是入门小模型

[Flash 模型仓库](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Flash-RL)提供另一套成品模型及运行配置。模型卡标注 **309B 总参数、15B 激活参数**，同为 MIT 许可证。MoE 的“激活参数”表示一次计算只使用部分专家，不意味着只需要存储这部分权重。不能看到 15B 就把它当作一张消费级显卡可以随意训练的 15B 稠密模型。[M5]

**参数统计提醒：**部分页面自动统计的打包张量数量，与模型卡描述的架构总参数数量不是同一个口径。本学习仓库使用模型卡的架构数字，不混用统计口径，也不把激活参数直接代入显存预算。

### 4. MiMo-V2.6-Distill-Qwen-9B：最相关的研究起点

[9B 模型卡](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Distill-Qwen-9B)明确说明：它是在 **Qwen3.5-9B** 上，使用 MiMo 生成的数据进行监督微调得到的模型，公开的是 **SFT checkpoint**，供后续 Agentic RL 使用。可以理解为“已经跟着老师学过一轮、可以继续做练习的学生”。你可以研究它的聊天模板、数据组成说明、任务表现，或在合适设备上做推理、微调与 RL；但直接下载不会让你体验它此前的预训练或蒸馏过程。[M3]

有一个容易误读的细节：发布文章列出后续 RL 实验的提升，不等于下载的 9B 权重就是那个 RL 结果。例如官方介绍 SWE-bench Verified 从 61.1 升到 66.2，而模型卡将公开检查点标为 SFT，并列出 61.1 的基线成绩。比较时必须区分**发布的权重阶段**与**另外进行的训练实验**。[M1][M3]

### 5. 技术报告：研究方法的说明书，不是新手教程

官方报告文件名为 **`MiMo_V2_6_technical_report.pdf`**，可在 [Pro 仓库的报告页面](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-RL/blob/main/MiMo_V2_6_technical_report.pdf)找到。它的用途是解释模型、训练方法、工程选择和实验结果，帮助研究者理解与检验方法；不能把一篇报告当作全量训练数据或一键复现程序。

**本次核验边界：**已确认官方报告链接与 PDF 文件页面存在，但 PDF 下载/渲染链路未成功，未完成全文逐页阅读。因此本仓库不冒充报告逐章精读，不给出未经核验的章节号、页码、表格或公式解释。下面的技术导读依据官方发布文章和模型卡中实际可读取的说明，而非二手文章对 PDF 的转述。[M1][M4][M6]

### 6. Live RL 仪表盘与罗福莉的 X 动态：观察研究进程

官方提供 [Live RL 页面](https://mimo.xiaomi.com/rl/)，并在发布文章确认公开展示了不足六天的生产 RL 运行。这类资源适合观察训练指标、评估、运行进度之间的关系；它不是从零搭环境、逐行讲代码的教学直播，也不是公开了全部预训练。X 账号与相关原帖入口见来源页，本次原帖访问受限，不把转载文字当作已经直接核验的原文。[M2][M7]

初次阅读可以只问三个问题：曲线测的到底是什么？训练题和评测题是否不同？更高奖励是否伴随着真正的任务成功，而不是学会绕过评分？

### 7. 7k+ RL 任务环境：让模型有题可做、有结果可查

官方宣布开放覆盖软件工程、漏洞复现、知识型工作、网页设计开发的 7k+ 任务环境。这里的“环境”不只是问答文本，还可能包含代码仓库、容器、工具、初始文件与评分程序，模型要通过多步操作完成任务。这对学习数据构造、自动化评测与奖励设计很有价值。[M1]

**但开放声明不等于本次已下载验证全部数据。**调研中找到了模型、框架、数据集适配器和外部任务示例，尚未逐一定位并验证这 7k+ 任务的完整下载清单、镜像可访问性、许可证和一键复现脚本。模型卡中的 SFT 数据配比/规模说明，也不等于对应原始 SFT 数据已经发布。不要把外部 DeepSWE 示例任务误称为小米的完整 7k+ 训练集。

### 8. `XiaomiMiMo/mimoagent`：负责“做题和记录过程”

[mimoagent](https://github.com/XiaomiMiMo/mimoagent)从 mini-swe-agent 分支发展而来，是面向工程的 rollout 框架：把 Agent、模型接口、执行环境和任务/评分器连接起来，保存任务尝试的轨迹。你可以在其中认识“模型输出一个工具调用后，谁执行命令、谁把结果送回模型、最终谁评分”。它本身不是解释反向传播的课程，也不等于单独运行它就更新了模型权重。[G1]

**启动前的实际问题：**README 的 Docker 快速开始引用 `example_configs/swe_docker.yaml`；本次对 `mimo-oss` 分支读取该精确路径返回 404。已读取的 `mini-swe-agent.yaml` 则使用 Kubernetes，不能视为原 Docker 配置的直接替代。故本文没有把 README 命令包装成“已验证可运行的入门教程”。[G2][G3]

### 9. `XiaomiMiMo/uni-agent`：负责“把 Agent 接到训练系统”

[uni-agent](https://github.com/XiaomiMiMo/uni-agent)提供 Agent 与训练/推理引擎之间的衔接和调度能力，包括 gateway、任务运行与示例配方。可把它理解成连接“模型做题现场”和“参数更新程序”的中间层。它适合之后学习训练数据如何从多步工具调用变成 token、mask、奖励，以及如何组织大量并发任务。[G4]

已实际读取 `examples/quickstart/training/train_qwen3p5_dense.sh`：该脚本默认模型是 **Qwen3.5-4B**，不是 MiMo 9B；默认 **8 节点 × 每节点 8 GPU**，并使用长响应、Ray、Megatron、异步 rollout 等配置。它证明这里有真实工程训练入口，也提醒我们：**名字中有 quickstart 不代表是新手或单卡最低配。**这些默认值不是“训练 9B 的最低硬件要求”，也不是已经核验的小米论文 9B 复现配方。[G5]

### 10. `XiaomiMiMo/verl`：负责“根据奖励更新参数”

[verl](https://github.com/XiaomiMiMo/verl)是这套 RL 训练栈中的策略优化组件。简化地说，前面的系统产生尝试过程与分数，训练器根据它们计算训练信号，再通过梯度更新模型。它适合在理解普通训练循环之后，继续研究 RL 算法与分布式训练。不应因为它公开了，就推断旗舰模型的所有生产配置、依赖数据及完整预训练过程均可一键复现。[G6]

### 11. Mini-harnesses 与应用演示：不要混为新的基础模型

官方同时介绍将系统提示、工具、上下文管理解耦的轻量 harness，以及在多个 harness 中训练的思路。它们改变的是模型做任务的“工作环境与约束”，不是 Transformer 的数学定义。MiMo Code、Desktop、API，以及游戏/设计/科研演示属于使用模型的应用入口或案例，不是另一套从随机权重训练 GPT 的教程。可以观看来建立兴趣，不必全部安装。[M1][M2]

## 二、把资源串起来：两条完全不同的流程

```text
从零预训练（你的第一条学习主线）
文本 → 分词/编码 → 输入和下一 token 目标 → 随机初始化的小 GPT
     → 预测 → 计算 loss → 反向传播 → 更新参数
     → 独立验证 → 保存 checkpoint → 重新加载并生成

MiMo 9B 后训练（进阶主线）
已经完成 SFT 的 9B → 在任务环境中尝试 → 记录多步轨迹
                  → 评分器给奖励 → 训练器更新参数
                  → 重新做未见过的题 → 比较表现
```

第一条主要教你**语言模型为什么会学、一次训练更新是什么**；第二条主要教你**已有模型如何通过交互反馈改进，以及工程系统如何支撑它**。两者互补，不是竞争关系。

## 三、零基础现在就能从 MiMo 学到什么

| 观察对象 | 先问的具体问题 | 能学到的东西 |
|---|---|---|
| 9B 模型卡 | 它从哪个模型开始？现在处于哪一训练阶段？ | 预训练、SFT、蒸馏、RL 的区别 |
| 一个任务及评分器 | 什么算成功？失败如何判断？ | 数据设计、测试与奖励的关系 |
| 一条 Agent 轨迹 | 哪一步是模型生成？哪一步是工具返回？ | Agent 的执行闭环与训练样本来源 |
| 基线与训练后评测 | 比的是同一任务、同一设置吗？ | 控制变量、样本外评估与指标解释 |
| 训练配置 | 哪里指定模型、数据、并发、响应长度、GPU 数？ | AI Infra 的职责与资源瓶颈 |

**暂时跳过：**万亿参数部署、1M 长上下文训练、分布式并行细节和大规模多任务 RL 配方优化。先获得能解释的小规模结果，比“启动了一个复杂命令但不知道发生什么”更符合这个学习目标。

## 四、报告导读：只带着问题进入，不按页硬读

先在官方摘要中找到“模型怎样做任务”“怎样评分”“如何评测”三个部分；完成第一次小 GPT 训练后，再回看梯度更新、批量、上下文长度；完成简单奖励实验后，才进入 GRPO、异步采样与奖励可靠性。

模型卡提到的 GRS、GAR 可以暂时概括为：用更细致的标准评判一组尝试，以及在同样完成任务的尝试中进一步区分质量。这是理解方向，不替代正式算法定义。MOPD2、复杂并行策略和长程任务中的细粒度归因，留作选读。[M4]

**最终判断：你可以从 MiMo 学到东西，也可以逐步做真实后训练；但最合适的起点不是下载最大的权重，而是先建立一套自己能解释、能修改、能评估的小训练循环。**
