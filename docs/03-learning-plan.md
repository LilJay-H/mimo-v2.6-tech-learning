# 03｜从零 ML 基础开始的学习方案

## 一、先确定目标：不是“复现一款顶级大模型”

这个方案的主目标是：**亲手训练一个很小的语言模型，能解释数据怎样进入模型、损失怎样驱动参数更新，并用未用于训练的数据检查它学到了什么。**之后再根据兴趣，延伸到聊天微调、强化学习和 Agent 训练工程。

你已有计算机专业背景，不必把自己当作编程零基础；缺的是机器学习概念与实验经验。对应的策略是“补足下一步需要的知识后立即动手”，而不是先学完一整套机器学习、深度学习、强化学习和分布式系统课程。

这里的时间均为**学习规划估算**，不是已在你的设备上实测，也不包括下载等待、GPU 排队或复杂安装故障。

## 二、推荐顺序：一条主线，两个分支

```text
必要 Python / 张量 / 梯度
          ↓
micrograd 的训练直觉 → makemore 的语言建模
          ↓
ng-video-lecture：小 GPT，从随机参数训练
          ↓
保存/重新加载 + 验证集 + 3 组控制变量实验
          ├── 对底层与效率更感兴趣：build-nanogpt → llm.c（选读）
          └── 对聊天与 RL 更感兴趣：nanochat 的小规模 SFT/聊天流程
                                              ↓
                          MiMo 的任务、轨迹、评分与训练器
                                              ↓
                               简单奖励实验 → 9B RL（条件成熟再做）
```

MiMo 发布说明和 9B 模型卡可以从第一周开始穿插阅读，不必等所有课程学完。它们承担“看见真实应用”的作用；Karpathy 小模型承担“看清基本机制”的作用。

原始课程前提与项目范围：[Zero to Hero](https://karpathy.ai/zero-to-hero.html)、[ng-video-lecture](https://github.com/karpathy/ng-video-lecture)、[nanochat](https://github.com/karpathy/nanochat)。

## 三、第一阶段：最小完整训练闭环，24–37 小时

| 阶段 | 学习与操作 | 建议投入 | 必须留下的成果 |
|---|---|---:|---|
| 0. 环境与现有技能检查 | Python 环境、PyTorch、CPU 张量运算；记录设备和版本 | 1–2 小时 | 一份环境记录，能运行一个张量例子 |
| 1. 梯度为何能让模型学习 | micrograd 必要内容：计算图、链式法则、loss 和更新 | 5–8 小时 | 手算一个简单导数，解释一次更新方向 |
| 2. 文字怎样成为预测问题 | makemore 第一部分；字符编码、概率、采样、损失 | 4–6 小时 | 一个字符级预测器，训练与生成日志 |
| 3. 小 GPT 的结构与训练 | ng-video-lecture；缩小配置，读清因果注意力与训练循环 | 8–12 小时 | 从随机参数训练的模型、loss 记录、前后样本 |
| 4. 让结果可复现、可比较 | 保存/加载；独立验证；三组单变量实验 | 4–6 小时 | checkpoint、三份实验记录、一份复盘 |
| 5. 用 MiMo 对照现实流程 | 阅读发布地图，画出 9B SFT→RL 的流程 | 2–3 小时 | 能区分模型、harness、环境、grader、trainer |

合计 24–37 小时。每周投入 6 小时，约 4–7 周；每周 8 小时，约 3–5 周。阶段 5 可穿插进行，不是最后才能看的资料。

**这已经是一个完整、真实的模型训练项目。**完整指实验流程完整，不指模型规模、能力、数据量与工业大模型一致。

### 验收标准

不要以“跑完了”“生成得像人话”作为唯一标准。结束时，应能独立做到：

1. 说明训练输入与目标如何错开一位，以及为什么不能把未来答案泄露给模型。
2. 解释 `zero_grad → forward/loss → backward → step` 的作用和顺序。
3. 说明训练集、验证集的用途，指出一次训练好、验证差的现象。
4. 退出程序后重新加载自己的权重和字符表，不重新训练也能生成。
5. 在固定比较条件下改变一个变量，说明观察到什么，以及哪些结论暂时不能得出。

达到这些标准，收获是**训练直觉、基础深度学习编程能力和实验习惯**，而不是已经掌握全部 AI Infra。

## 四、到底先补哪些知识？

### 开始之前只需要这几类

| 知识 | 最小要求 | 暂时不必学到的深度 |
|---|---|---|
| Python | 函数、列表/字典、类、导入、读文件、虚拟环境 | 高级元编程、复杂框架设计 |
| 线性代数 | 向量/矩阵、矩阵乘法、维度匹配 | 全套矩阵分析证明 |
| 微积分 | 导数意义、复合函数链式法则 | 优化理论的严格收敛证明 |
| 概率 | 概率分布、条件概率、期望的直觉 | 高等统计推断 |
| PyTorch | Tensor 的 shape、索引、广播、矩阵乘、自动求导 | 自定义 CUDA 算子、分布式并行 |

只有当某一项使当前练习无法进行时，才针对它补课。课程作者对 Zero to Hero 的前提也是 Python 编程与入门数学，而不是先完成研究生机器学习课程。[原始课程说明](https://karpathy.ai/zero-to-hero.html)

### 在对应阶段现学现用

看见 `cross_entropy` 时补 softmax 与负对数概率；看见 `loss.backward()` 时补计算图；看见注意力矩阵时先写出每个维度；看见 checkpoint 时补权重、配置与优化器状态的区别。不要遇到一个词就向外展开十篇论文。

RL 之前再补“策略、采样轨迹、奖励、优势”的直觉；多 GPU 之前再补进程、通信、数据并行和显存分摊。这个顺序能避免环境术语压过模型学习本身。

## 五、第二阶段的选择：不必把所有仓库学一遍

### 分支 A：想知道 GPT-2 如何实现得更标准、更高效

选择 `build-nanogpt`，建议 12–20 小时主动学习，**不以完整跑完默认 10B tokens 为目标**。重点是逐步阅读提交、核对张量维度、理解权重共享、梯度累积和吞吐量，然后做一两个缩小实验。参考 [项目 README](https://github.com/karpathy/build-nanogpt) 与 [训练脚本](https://github.com/karpathy/build-nanogpt/blob/master/train_gpt2.py)。

验收：能解释有效批量和微批量的差别，能测量每秒 token 数，能指出“更快”是否来自计算优化还是减少了实验工作量。

### 分支 B：想尽快知道“续写器怎样变成聊天模型”

选择 `nanochat`，建议 6–12 小时进行小规模流程体验与代码阅读。把它作为已经理解训练循环之后的系统拼装项目，不要再次从所有基础概念重头学起。阅读 `runcpu.sh` 中数据、分词器、预训练、SFT、评测、聊天之间的衔接；缩短运行时要同时检查评测频率、批量和数据量。[CPU 教学流程](https://github.com/karpathy/nanochat/blob/master/runs/runcpu.sh)

验收：保存 SFT 前后的相同提示词输出，解释监督微调究竟在哪些 token 上计算损失，区分“按对话格式回答”与“知识、推理能力真的提升”。很小的模型可能只学会格式，不能因此宣称获得通用助手。

**针对本次对 MiMo/RL 的兴趣，优先推荐分支 B；分支 A 作为你对系统或模型实现产生具体问题时的选读。**

## 六、第三阶段：从 MiMo 进入真实 Agent 训练工程

### 先做不更新权重的环境与轨迹实验

在配置和依赖已可运行的条件下，建议 4–8 小时：选择一个安全的代码修复/小工具任务，先用参考解跑评分器，再让模型做一次，读出完整轨迹，找出模型输出、工具返回、终止原因与最终分数。可以调用已有 API，不需要为了看一条轨迹就先在本地部署 9B。

该阶段学习的是**任务执行与评测基础设施**，不是训练。当前 mimoagent README 示例存在配置读取缺口，应按 [动手实验中的检查门槛](04-hands-on-labs.md)核验，而不是遇到错误后盲目反复安装。[mimoagent](https://github.com/XiaomiMiMo/mimoagent/tree/mimo-oss)

### 再做一个小型、真的更新参数的 RL 实验

建议先用具备足够基础能力的小模型和简短可验证任务，例如一位数算术或格式受限的字符串操作。先测基线；对每个问题生成多个答案；由程序评分；根据相对表现更新；再测试未用于训练的题。建议学习投入 8–16 小时，前提是普通训练、SFT 和奖励函数都已理解。这个估算不包括修复复杂框架兼容性。

为什么不直接给弱模型上 GSM8K？因为它可能所有答案都错，得到几乎相同的奖励，没有可区分的学习信号。先选择有些题能做对、有些会做错的任务，理解反馈怎样改变概率，比追逐一个高难基准更有意义。

nanochat 的 [chat_rl.py](https://github.com/karpathy/nanochat/blob/master/scripts/chat_rl.py)可以帮助阅读这个闭环，但脚本的任务、算法简化和模型能力要求必须单独检查；它不是默认 speedrun 的必经步骤，也不是开箱即用的 MiMo 9B 配方。

### 最后才决定是否做 MiMo 9B RL

进入前要满足：普通训练能排错；数据和评分器能独立运行；知道要训练哪些参数；模型/推理引擎版本相容；短轨迹不会超预算；有可用设备；有独立测试集。

进入后先做到**单一任务类型、小数据子集、短上下文、少量 rollout、少量更新、训练前后评估**，再逐一放大。换成 LoRA、更小模型或更短任务属于新的教学实验，不应标成官方论文复现。

不满足这些条件时，停止在“代码结构理解 + 单任务轨迹 + 小型奖励实验”完全合理。这不是未学到东西，而是已经完成了适合当前基础的学习目标。

## 七、如何让 AI 帮忙而不是替你完成学习

每一轮保持同一顺序：**先预测 → 自己运行 → 记录结果 → 向 AI 提具体问题 → 自己解释并验证。**

可以让 AI 帮你解释报错、画张量维度表、设计测试、审查数据泄漏，或指出你对代码的复述哪里不准确。不要让它在你尚未建立判断标准时，把整个教程重写为一个更复杂的训练框架。

可以直接使用下面的学习提示：

> 我正在学习这个训练脚本。我会先给出自己的解释。请先指出解释中的错误，再给一个小问题或实验让我验证；不要直接替我重写整个项目。修改代码时说明每处改动会影响输入、loss、梯度、参数还是评测，并保持改动最小。

每次结束写三句话：今天模型接收了什么？哪一个量真正改变了？我凭什么判断变化有用？写不出来时，优先回看数据和训练循环，不要继续加新框架。

## 八、三组值得做的“边玩边学”实验

**实验一：学习率。**其余设置一致，对照较低、基线、较高学习率，记录 train/val loss 和样本。目标不是找“万能学习率”，而是观察更新太小、适中、过大可能有什么迹象。

**实验二：上下文长度。**保持模型宽度等设置一致，改变可看到的前文长度；记录质量、吞吐与内存。比较时明确按“相同步数”还是“相同 token 数/时间预算”，两者回答的问题不同。

**实验三：数据。**先用小规模授权文本训练，再更换题材或缩小训练集；检查文本风格变化、过拟合与未见文本损失。不要上传私人聊天、API Key 或未经许可的资料。

以上实验都需要固定验证集，不把反复用于调参的数据称作最终测试集。记录模板见 [experiment-log.md](../templates/experiment-log.md)。

## 九、最终能学到什么，不能承诺什么

最小主线完成后，你应拥有模型训练的基本直觉、PyTorch 小项目经验、控制变量与验证意识。加入 nanochat 后，会认识数据—预训练—SFT—评测—推理的系统连接；加入 MiMo 任务实验后，会认识 harness、容器、轨迹、评分与训练器的分工。

这些经历能帮助你在以后正式学习机器学习、深度学习和计算机系统时，把抽象知识对应到见过的现象；但不等于已经掌握前沿 RL 理论、生产分布式系统或能够独立训练旗舰模型。也不保证每次实验都让指标提升：能可信地解释一次失败，同样是学习成果。
