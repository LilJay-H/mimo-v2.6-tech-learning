# 05｜算力、时长、费用与复现边界

## 一、先给结论

**入门阶段不需要先买设备或租集群。**从 CPU/已有消费级 GPU 上的小 GPT 开始，先确认学习目标是否值得继续投入。MiMo 的发布提高了研究资源的可获得性，但不意味着运行大模型后训练的算力成本消失了。

本页的硬件分档是学习规划建议，不是对你的具体设备做过的兼容性测试。实际显存与 RAM 请用系统工具检查，不仅根据显卡型号推断。

## 二、“能运行”和“能训练”差在哪？

推理主要需要模型权重、临时计算空间，以及生成过程的缓存。训练还要保存或重算用于反向传播的中间结果，存储梯度和优化器状态；RL 还可能同时需要生成多条轨迹、评判它们、保留额外模型与任务环境。

所以同一个 9B 模型，短文本量化推理、短序列 LoRA 微调、全参数 SFT、长轨迹 RL 是四种明显不同的资源问题。不能由其中一种能运行，推导另外三种也可以。

### 一个只用于建立数量级的计算

假设恰好有 90 亿个参数：

```text
BF16 权重：9,000,000,000 × 2 字节 = 18 GB（十进制）
4-bit 权重裸数据：9,000,000,000 × 0.5 字节 = 4.5 GB
```

这还没有包含非量化模块、量化元数据、KV cache、临时缓冲区和框架额外开销。9B 是名称级近似，实际参数总数也可能略不同。**4.5 GB 裸权重不等于完整系统能在 4.5 GB 显存中运行，更不等于 8 GB 显存可以完整 RL。**

再举一种常见混合精度 Adam 状态预算作说明：权重 2 字节、梯度 2 字节、两个 FP32 动量共 8 字节、FP32 主权重 4 字节，合计约 16 字节/参数，对 9B 是约 144 GB；还没有加入激活。具体实现不一定保留这些副本，也可能用分片、卸载、其他优化器或参数高效训练，因此 **144 GB 不是统一的最低门槛**，只是说明训练为什么不能只看裸权重。

数字是按给定假设的算术推导，不是 MiMo 官方显存测量。MiMo 9B 的具体模型与 dtype 以 [官方模型仓库](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Distill-Qwen-9B)为准。

## 三、按资源选实验，而不是按热度选模型

| 资源档位 | 建议优先做什么 | 不应默认承诺的事情 |
|---|---|---|
| 只有 CPU，普通内存 | micrograd、makemore、缩小字符级 GPT、读取任务与评分器 | 合理时间内复现大规模 GPT-2 或 9B RL |
| 一张约 8 GB 消费级 GPU | 小 GPT 加速、缩小训练与评估；观察显存/吞吐 | 完整 9B 全参训练、长上下文、多 rollout RL |
| 单卡 12–24 GB | 更大的教学实验；评估合适模型的短序列参数高效训练 | 9B 任意精度、任意长度和任意并发都能跑 |
| 单卡 24–48 GB | 有条件评估 9B 推理和部分微调方案 | 单凭容量就证明整套 MiMo RL 栈兼容 |
| 80 GB 级或多卡服务器 | 在预算与配置明确后尝试更接近研究的后训练 | 一张 80 GB 卡必然容纳任意全参 Adam/RL 配方 |
| 多节点 GPU 集群 | 研究并行训练和长程多任务 RL | 初学者应该从这个阶段起步 |

LoRA/QLoRA 会改变需要训练的参数及资源分配，但不会自动解决推理引擎兼容性、长序列缓存、环境并发与任务评分问题。本次没有验证 MiMo 9B + 任意特定 LoRA/RL 框架在上述设备上的可运行性，因此不提供虚构的一键兼容承诺。

## 四、上游的真实默认配置告诉了我们什么？

### Karpathy：教学配置与性能配方不同

`ng-video-lecture/gpt.py` 默认比本方案第一轮配置大；减小模型后，仍保留训练的基本机制。[小 GPT 源码](https://github.com/karpathy/ng-video-lecture/blob/master/gpt.py)

`build-nanogpt/train_gpt2.py` 当前代码包含约 10B tokens 的训练安排及多 GPU 支持；教程中用于说明某个阶段的时间/成本，不能不核对工作量就套在最终脚本上。[GPT-2 训练源码](https://github.com/karpathy/build-nanogpt/blob/master/train_gpt2.py)

nanochat 有单独的 [CPU 教学脚本](https://github.com/karpathy/nanochat/blob/master/runs/runcpu.sh)与 [8-GPU speedrun](https://github.com/karpathy/nanochat/blob/master/runs/speedrun.sh)。它们服务不同能力和运行预算目标，不是相同成果的两个等价启动方式。

### MiMo：quickstart 名称不意味着单卡教程

本次实际读取的 uni-agent `train_qwen3p5_dense.sh` 默认包括：

```text
MODEL_PATH: Qwen3.5-4B
NNODES: 8
NGPUS_PER_NODE: 8
MAX_RESPONSE_LENGTH: 128K
CONCURRENCY: 256
TRAIN_PROMPT_BSZ: 64
N_RESP_PER_PROMPT: 8
```

[具体脚本](https://github.com/XiaomiMiMo/uni-agent/blob/mimo-oss/examples/quickstart/training/train_qwen3p5_dense.sh)。这是一个工程模板的默认值，**不是 MiMo 9B 最低要求，也不是证实必须花 64 张卡才能进行任何 RL 教学实验**。但它足以说明不能直接作为初学者的低成本第一步。

同样不能只把 `NNODES=1` 就称为“已适配单机”：张量/上下文并行、批量可整除性、模型支持、推理引擎、数据路径与环境服务都可能需要同步调整。

## 五、怎样估算你这一次实际要跑多久？

先固定配置，跑一小段包含预热的训练。在稳定阶段测量吞吐，不把首次编译或纯下载时间当成训练速度。CUDA 是异步执行的，计时边界要正确同步，或使用框架提供的可靠计时方式。

对于预训练，先计算计划处理的 token 数：

```text
每个优化步骤的 token 数
= 每设备微批量 × 序列长度 × 梯度累积次数 × 数据并行设备数

总训练 token 数 = 每步 token 数 × 优化步骤数

训练时间估算 = 总训练 token 数 ÷ 实测每秒 token 数
总墙钟时间 ≈ 下载/预处理 + 初始化/编译 + 训练 + 评测 + 保存
```

举例：批量 8、长度 64、无累积、单设备、300 步，共处理 153,600 个训练 token。测到速度后才能据此估时；不能把这个例子写成在任何 CPU 上固定需要几分钟。评测和生成也会额外耗时。

对于 Agent RL，仅用“参数量 × 步数”估算远远不够。还要测每题尝试次数、每条轨迹 token 数、工具/容器时延、评分时延、失败重试和模型同步开销。先用很少的任务做端到端测量，再估预算。

## 六、费用怎么控制？

本次不提供未经实时核价的云 GPU 套餐推荐。已有电脑上的最小主线不需要额外购买硬件；是否产生电费、存储、网络或 API 费用取决于你的实际运行方式。

云服务计算方法：

```text
总费用 ≈ GPU 数 × 单卡每小时价格 × 运行小时
        + CPU/内存服务 + 存储 + 镜像/网络传输
        + API/评分模型调用 + 失败重试
```

有些平台报价已包含整机多卡，有些按单卡计费，不能重复乘 GPU 数。作者历史运行成本只作参考，不当作当前报价。

预算顺序建议：**先本地验证训练 → 再验证评分器 → 再测单条轨迹 → 最后购买明确时长和上限的算力**。启动前设终止条件，完成后关闭计算实例；保存必要日志与 checkpoint，不让空闲资源持续计费。

## 七、什么才算复现，什么只是完成了教学实验？

| 达成的事情 | 应该如何描述 |
|---|---|
| 调用 MiMo API 完成一个任务 | 推理/应用体验 |
| 用 mimoagent 记录和评分一条轨迹 | Agent 执行与评测实验 |
| 从随机参数训练自己的小 GPT | 小规模预训练实验 |
| 用小模型和自定义任务做奖励更新 | RL 教学实验 |
| 把官方配方换为 LoRA/更小模型/更短上下文 | 受原方案启发的改编实验 |
| 对齐检查点、数据、任务环境、算法、采样和评估设置，并核对结果 | 才能进一步讨论对应范围的研究复现 |

**跑通流程不是复现分数；复现某个实验也不是复现整条工业训练链。**这个区分不是降低学习价值，而是使学习成果可信。

## 八、复现记录至少保存这些

保存代码提交 SHA、依赖版本、模型及 tokenizer 版本、数据来源与切分、随机种子、模型结构、学习率、批量与序列长度、设备配置、运行时间、评测方法和失败日志。推理服务还应记录模型名、chat template、采样参数和工具限制。

权重、原始轨迹和密钥不适合直接进公共 Git 仓库。提交经清理的实验摘要、配置、图表和代码即可。模板见 [实验记录](../templates/experiment-log.md)。
